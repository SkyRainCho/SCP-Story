# Kindle Scribe Grayscale Image Encoding Design

## Goal

Reduce the packaged size and image I/O cost of the existing Kindle Scribe stable
edition with the smallest possible effect on layout and rendering. The change is
limited to raster encoding inside `--kindle-stable`; it must not alter image pixel
dimensions, XHTML structure, CSS, navigation, pagination rules, or the existing
standard EPUB and `--kindle` outputs.

The existing output names remain unchanged:

- `output/epub/SCP基金会档案精选-Kindle-Scribe.epub`;
- `output/azw3/SCP基金会档案精选-Kindle-Scribe.azw3`;
- `output/reports/SCP基金会档案精选-Kindle-Scribe-report.json`.

## Selected Approach

All raster variants generated by the Kindle Scribe stability pipeline will use a
grayscale encoding while retaining the dimensions selected by the existing
screen-aware and per-page decode-budget planner.

- JPEG and MPO first-frame variants are encoded as 8-bit grayscale (`L`) baseline
  JPEG at quality 85, with optimization enabled and progressive encoding disabled.
- Opaque PNG variants are encoded as 8-bit grayscale (`L`) PNG.
- PNG, GIF, or other supported raster frames with effective transparency are
  encoded as grayscale plus alpha (`LA`) PNG. Alpha values are preserved rather
  than flattened onto white, because some source pages use non-white backgrounds.
- Animated GIFs continue to use only their first frame, which is converted to `L`
  or `LA` according to transparency.
- EXIF orientation and the existing resize operation are applied before grayscale
  conversion.

The conversion will use Pillow's normal luminance conversion. It will not apply
thresholding, posterization, palette quantization, automatic contrast enhancement,
dithering, sharpening, or pre-rendered e-ink patterns. These operations can alter
line art, gradients, text-like images, and page tone more noticeably than a plain
grayscale conversion.

## Alternatives Considered

### Add a separate monochrome CLI mode

A new `--kindle-mono` mode would preserve the current stable artifact byte-for-byte,
but it would add another CLI combination, output family, report, and long-term test
surface. The user requested an optimization of the current Scribe edition, so a
separate mode is unnecessary.

### Convert only large images or photographs

Selective conversion would retain color data that a Kindle Scribe cannot display,
while requiring brittle image classification rules. It would also make file-size
and cache behavior less predictable. A consistent grayscale stable profile is
simpler and better matched to the target device.

### Flatten transparent images onto white

Flattening can produce smaller or simpler images, but it creates visible white
rectangles on chapters with dark or tinted backgrounds. Preserving alpha has the
smallest rendering impact and is therefore selected.

## Variant Identity and Caching

Generated filenames must include the grayscale encoding profile in their
deterministic identity. This prevents a grayscale variant from sharing a filename
with an older RGB/RGBA stable variant for the same source URL, purpose, and bounds.
The visible filename will include a `gray` marker and the digest input will include
the profile name.

Variant deduplication remains based on source href and the existing variant spec.
Because all variants within stable mode use the same grayscale profile, no new
planner dimension is required.

## Transparency Detection

Transparency is considered effective when the selected first frame has an alpha
channel or palette/transparency metadata. The implementation will convert such a
frame to RGBA, derive luminance from its RGB channels, and combine the luminance
channel with the original alpha channel into `LA`. Opaque frames are converted
directly to `L`.

This preserves partial alpha, not only fully transparent pixels.

## Decode Budget

The current conservative estimate of four decoded bytes per pixel remains
unchanged. Some Kindle and conversion pipelines may expand grayscale assets to a
multi-channel internal surface, so reducing the estimate to one or two bytes per
pixel would overstate the crash-resistance improvement.

Grayscale encoding is expected to reduce EPUB/AZW3 storage and image-read cost. It
is not treated as a substitute for the existing pixel bounds, facility thumbnails,
or per-page hard decode limit.

## Reporting

The stable report's `kindle_performance` object will add:

- `image_encoding_profile`: `grayscale-preserve-alpha`;
- `grayscale_variant_count`: number of successfully rendered grayscale raster
  variants;
- `grayscale_alpha_variant_count`: number of those variants encoded as `LA` PNG.

Existing report fields and decode estimates remain compatible.

## Compatibility and Failure Handling

Only `prepare_stable_kindle_assets` and its generated variants change. Standard
EPUB assets and current high-quality Kindle assets retain their existing encodings.
SVG passthrough and validation behavior is unchanged.

If grayscale conversion fails, the existing stable missing-asset handling applies:
the source URL is added once to `missing_assets`, the failed image reference is
removed through the Kindle fallback, and unrelated variants continue processing.
EPUB/AZW3 atomicity behavior is unchanged.

## Testing and Verification

Unit tests will verify:

- JPEG output is `L`, retains the planned dimensions, remains baseline JPEG, and
  uses a grayscale-specific deterministic filename;
- opaque PNG output is `L` and retains its dimensions;
- transparent PNG output is `LA` and preserves the original alpha values;
- animated GIF output is a one-frame grayscale PNG;
- EXIF orientation and MPO handling still work;
- stable reports contain the encoding profile and variant counts;
- standard EPUB and `--kindle` behavior are unchanged.

Final verification will run the complete test suite and rebuild the Featured
Kindle Scribe EPUB/AZW3. The produced EPUB will then be audited to confirm that:

- every generated stable raster is `L` or `LA`;
- all XHTML files parse successfully and all packaged image references resolve;
- image pixel dimensions and page reference structure still follow the existing
  stable planner;
- the facilities page card/icon counts remain unchanged;
- the stable EPUB and AZW3 are nonempty and their sizes are compared with the
  previous build.

## Non-goals

This change does not resize images beyond the current stable policy, change CSS or
XHTML layout, split pages, adjust contrast, create 1-bit images, add dithering, or
alter source downloads and manifests. Further optimization of specific heavy pages
such as the points-of-interest badge grid remains a separate task.
